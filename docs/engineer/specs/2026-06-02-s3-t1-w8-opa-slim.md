# Spec: Phase S3-T1 — W8 OPA slim — policy hot-reload (single-tenant)

_Author: design subagent, 2026-06-02. Source-of-truth:_
- `docs/engineer/briefs/2026-06-01-self-host-first.md` §3 S3-T1 (W8 T-remaining slim — OPA Authorizer impl + policy hot-reload; SKIP multi-tenant `tenant_id` propagation).

- W8 T1 shipped: PR #316 (Authorizer interface + OPA Rego embed + atomic copy-on-write store swap; `Reload(ctx, tenant)` already exists).

**Zero new schemas. Zero new substrate event kinds. Zero new migrations. ~60% smaller than umbrella W8.**

## 1. Prior art adopted

Per `feedback_research_design_principles` — every primitive cites either an upstream OPA pattern or a regatta primitive already shipped. No bespoke invention.

| Primitive | Adopted from | What we take | Why not bespoke |
|---|---|---|---|
| ETag / SHA short-circuit on reload | [OPA bundle `If-None-Match` pattern](https://www.openpolicyagent.org/docs/latest/management-bundles/) | Hash the bundle directory; skip recompile + swap when hash unchanged | OPA's own bypass — proven across the OPA install base; saves ~10-20 ms per no-op reload |
| Filesystem watcher | [`github.com/fsnotify/fsnotify` v1.10.x](https://pkg.go.dev/github.com/fsnotify/fsnotify) (BSD-3) | Cross-platform inotify (linux) / kqueue (darwin) / ReadDirectoryChangesW (windows) abstraction; debounced edge-triggered reload | Standard Go file-watcher; same dependency Caddy / Hugo / Prometheus / many OSS use |
| Signal-driven reload (SIGHUP) | nginx / Caddy / dnsmasq operator-reload convention | `os/signal.Notify` on `syscall.SIGHUP`; unix-only (windows = compile-tag-gated out, see §3.6) | Universal "reload config now" signal for daemons; works in systemd / foreground / docker without extra surface |
| Atomic store swap (already shipped) | W8 T1 `internal/authz/store.go` — `atomic.Pointer[opaStore]` CAS | Reuse verbatim; hot-reload only changes the _trigger_, not the swap mechanism | T1 closed R4 + R8 (stale store, lock contention) — no new design needed |
| Default-deny `embed.FS` fallback (already shipped) | W8 T4 `internal/authz/policies/embedded/` | Watcher missing / disk bundle absent ⇒ continue serving `embed.FS` default-deny per §3.5 of umbrella | Closes "operator forgot to mount policy dir" failure mode at zero cost |
| Shadow-evaluation dry-run (A+ tier only) | OPA bundle activation-failure-rollback pattern (a signed-bundle activation that fails verification keeps the prior bundle active) | Compile + sample-eval candidate bundle in parallel store; promote only if eval matches a fixed sample set | OPA's own activation-failure pattern; we extend with sample-eval guard |

**Why two trigger mechanisms (B + A)**, not one: SIGHUP is the floor that works in any unix deployment (systemd, foreground dev, Docker) and is the unambiguous operator intent signal. Fsnotify is the UX upgrade (no manual reload) for the common case. **Polling intentionally NOT adopted** — that is OPA's answer for _remote_ bundle services (HTTP polling against `bundle.tar.gz`); single-tenant disk-backed bundles don't need it. If/when Phase X opens multi-tenant remote bundles, polling re-enters per the umbrella's §3.3 / F-HR2.

## 3. Hot-reload design — signal + fsnotify, embed.FS fallback

### 3.1 Decision: signal-driven (SIGHUP) + filesystem watcher (fsnotify), NOT polling

Per `feedback_decision_priority` (UX > ease > performance > best-practices > velocity), and per `feedback_research_design_principles` (adopt proven OSS):

| Option | UX | Ease | Performance | Verdict |
|---|---|---|---|---|
| **SIGHUP only** | Floor: operator runs `kill -HUP $(pgrep regatta)` after edit | Easiest impl (~30 LoC) | Zero idle cost | **B tier — ships**. Operators in systemd / nixos / Docker land already use SIGHUP for nginx / Caddy / dnsmasq. |
| **fsnotify on policy dir** | Best: save `.rego`, reload happens | Medium impl (~150 LoC + tests) | One inotify fd; debounced 250 ms | **A tier — target**. Standard Go pattern; matches umbrella §1.2 non-goal #2 "deferred" → promoted to in-scope. |
| **Polling (`ticker.C`)** | Worst: 60-120s lag, wasteful idle | Easy impl | Constant cost even when nothing changes | **Rejected for single-tenant disk-backed bundles.** Polling is OPA's answer for remote bundle services; disk doesn't need it. Re-enters scope if/when Phase X opens remote bundles. |
| **HTTP admin endpoint `POST /admin/reload`** | Operator: extra HTTP call | Medium impl + auth surface | Per-request | **Followup (F-HR1).** Requires admin RBAC inside the Authorizer-it-is-protecting — chicken-and-egg risk. Deferred. |

**Both SIGHUP + fsnotify land together** in T-HR. SIGHUP is the floor (`os/signal.Notify`); fsnotify is the watcher. They share the same `Reload` callback — the trigger is duplicated but the reload code path is one.

### 3.2 Architecture

```
                ┌───────────────────────────────────────────────┐
                │  policy directory  ($REGATTA_POLICY_DIR or    │
                │   --policy-dir; defaults to embed.FS only)    │
                │                                               │
                │  regatta/v1/default/{approval,run}.rego       │
                │  regatta/v1/default/data.json                 │
                └────────────────┬──────────────────────────────┘
                                 │
            ┌────────────────────┼────────────────────┐
            │                    │                    │
   inotify/kqueue/RDC*W      SIGHUP              boot-time
   (fsnotify watcher)    (os/signal)           (Hydrate once)
            │                    │                    │
            └─────────┬──────────┴────────┬───────────┘
                      │                   │
                      ▼                   │
               debounce 250ms ────────────┤
                      │                   │
                      ▼                   ▼
              policies.LoadFromDisk(dir)
                   │
                   │ on success ──► OPAAuthorizer.Reload(ctx, "default")
                   │                    │
                   │                    ▼
                   │             atomic store CAS (T1 shipped)
                   │
                   └─ on error ──► log + OTel event;
                                   continue serving prior bundle
                                   (failure-mode = retain-last-good)
```

* `RDCW` = `ReadDirectoryChangesW` on Windows; fsnotify abstracts.

### 3.3 Components

#### 3.3.1 `disk.Loader` — concrete `BundleLoader` impl (NEW)

T1 already defines the loader seam: `BundleLoader.ActiveBundle(ctx, tenant) (sha string, files map[string]string, err error)` in `internal/authz/opa.go:22-27`. `OPAAuthorizer.Reload(ctx, tenant)` re-calls `loader.ActiveBundle` and CASes the store. **T-HR ships a second `BundleLoader` impl** (alongside T1's `defaultLoader`) that reads from disk + falls back to `embed.FS`.

```go
// internal/authz/policies/disk/loader.go (NEW)
package disk

// Loader reads .rego + data.json from a directory tree rooted at
// regatta/v1/. Falls back to T4's embedded default-deny bundle when
// the directory is empty / missing / unreadable.
//
// Implements internal/authz.BundleLoader.
type Loader struct {
    Dir   string // absolute path; "" ⇒ embed.FS only (passthrough to fallback)
    // Fallback is the T4 embedded bundle (DefaultRegoFiles +
    // DefaultBundleSHA256 from internal/authz/policies/embedded).
    Fallback authz.BundleLoader
}

// ActiveBundle satisfies authz.BundleLoader. tenant MUST be "default"
// for the slim variant; any other value returns ErrTenantUnknown
// (Phase X opens this up).
func (l *Loader) ActiveBundle(ctx context.Context, tenant string) (sha string, files map[string]string, err error)
```

- File walk gated to `.rego` + `data.json` extensions; rejects: dot-prefixed files, files ending `.swp` / `.tmp` / `~`, anything under `.git/`.
- SHA-256 computed over canonical-JSON of `{path → sha256(content)}` sorted by path (same shape T4's `DefaultBundleSHA256` uses — see `internal/authz/policies/embedded/embed.go`).
- Empty / unreadable dir ⇒ delegate to `Fallback.ActiveBundle(ctx, tenant)`.
- `Dir == ""` ⇒ same as fallback (no watcher started in §3.3.4).

#### 3.3.2 `policies.Reloader` — signal + fsnotify goroutine (NEW)

```go
// internal/authz/policies/reload/reloader.go (NEW)
package reload

type Reloader struct {
    Authorizer *authz.OPAAuthorizer
    Loader     *disk.Loader
    Tenant     string                      // always "default" in slim
    Debounce   time.Duration                // default 250ms
    Logger     *slog.Logger                 // uses existing OTel-aware logger
}

// Run blocks until ctx is canceled; spawns the watcher goroutine +
// signal handler. Idempotent (Reload is a no-op if SHA unchanged).
func (r *Reloader) Run(ctx context.Context) error
```

Internals:
- **fsnotify watcher**: `fsnotify.NewWatcher()`; `Add(dir)` on the policy dir. Coalesce events via a debounce timer (`time.AfterFunc(250ms, doReload)` rearmed on each event). Reload triggers on `Create | Write | Remove | Rename` events touching `.rego` or `data.json` files; ignores `.swp`, `.tmp`, `~`, hidden files.
- **Signal handler**: `signal.Notify(c, syscall.SIGHUP)`; on each SIGHUP, fire `doReload` immediately (no debounce — operator intent is explicit).
- **`doReload`**: re-hash via `Loader.SHA256()`; compare against `Authorizer.CurrentRevision(tenant)`; equal ⇒ short-circuit no-op + log. Different ⇒ `Loader.Load()` + `Authorizer.Reload(ctx, tenant)`. Errors logged + emitted as OTel span event `regatta.authz.reload.failed`; prior bundle stays active (retain-last-good).
- **Shutdown**: ctx cancel ⇒ watcher.Close + signal.Stop + goroutine returns.

#### 3.3.3 New `Authorizer` method — `CurrentRevision`

T1 already tracks revision per (tenant, action) inside `opaStore.queries[tenant/action]` (the `recordRevisionForTest` path the T1 PR body documents). T-HR adds a small read-only accessor — production-pinned, not test-only:

```go
// internal/authz/opa.go (MUTATE — additive)

// CurrentRevision returns the 8-char SHA prefix of the active bundle
// for tenant. Returns "" if no bundle is loaded for that tenant.
// Lock-free read via atomic.Pointer.Load() — same hot-path discipline
// as Check. Slim variant always passes tenant="default"; kept as a
// parameter for Phase X forward-compat.
func (a *OPAAuthorizer) CurrentRevision(tenant string) string
```

No store-shape change; this just promotes the existing internal field to a public accessor. The Reloader uses it to short-circuit "same SHA ⇒ no work" before calling `Reload`.

#### 3.3.4 Wire-in `cmd/regatta/serve.go`

```go
// cmd/regatta/serve.go (MUTATE — one block, ~15 LoC)
// (Existing OPAAuthorizer wiring per T1 stays.)
loader := &disk.Loader{Dir: cfg.Safety.AuthzPolicyDir, Embed: embedBundle}
if err := authorizer.Hydrate(ctx); err != nil { ... }

if cfg.Safety.AuthzPolicyDir != "" {
    reloader := &reload.Reloader{Authorizer: authorizer, Loader: loader,
                                 Tenant: "default", Debounce: 250*time.Millisecond,
                                 Logger: srv.Logger}
    go func() {
        if err := reloader.Run(ctx); err != nil {
            srv.Logger.Error("policy reloader exited", "err", err)
        }
    }()
}
```

`AuthzPolicyDir == ""` ⇒ embed.FS-only mode; no watcher, no signal handler. (Matches umbrella §3.6's `safety.authz.policy_dir` config field convention — cost-gov mirror.)

### 3.4 Audit / OTel — slim subset

Umbrella §3.7 enumerates 6 OTel attrs. Slim variant drops `regatta.authz.tenant` (always `"default"` — useless cardinality) and emits the rest unchanged from T1. Hot-reload adds:

| Attribute / event | Type | When | Notes |
|---|---|---|---|
| `regatta.authz.reload.trigger` | string | every reload | `"sighup" \| "fsnotify" \| "boot"` |
| `regatta.authz.reload.revision_before` | string | every reload | 8-char SHA prefix (R7 carry-over) |
| `regatta.authz.reload.revision_after` | string | every reload | 8-char SHA prefix; equals `_before` on no-op |
| `regatta.authz.reload.duration_micros` | int | every reload | Load+compile+swap latency |
| span event `regatta.authz.reload.failed` | event | reload error path | Carries error message; bundle unchanged |

**Audit row for denials**: slim variant logs denials to `srv.Logger` (structured JSON via `slog`) + OTel span attrs only. Substrate `kind=authz_denied` event row is deferred to Phase X (S3-T2 substrate cutover scope intentionally excludes authz). Operators can grep the structured log; the audit signal exists, the storage primitive is just stderr+OTel-collector instead of `substrate_events`.

### 3.6 Platform portability (Windows)

`syscall.SIGHUP` is unix-only — Go's `os/signal` on Windows will refuse the constant at compile-time. Reload-by-signal compiles behind a build tag:

- `internal/authz/policies/reload/reload_unix.go` — `//go:build !windows` — registers `syscall.SIGHUP`.
- `internal/authz/policies/reload/reload_windows.go` — `//go:build windows` — no-op signal goroutine; logs `"authz: SIGHUP reload unavailable on windows; use fsnotify or restart"` once at boot.

Fsnotify is cross-platform (inotify / kqueue / ReadDirectoryChangesW), so windows still has the fsnotify trigger. This mirrors PHASE-S-RELAX windows-CI drop per `feedback_gate_relaxation_phase_s` — windows is not a self-host-blocker, but the build still compiles cleanly there.

### 3.7 Atomic-rename editor write pattern

Many editors (vim with `backupcopy=no`, neovim default, IntelliJ, VSCode "Atomic save") write `tmpfile` ⇒ `rename(tmpfile, target)`. fsnotify on linux emits `Create tmpfile` + `Rename tmpfile -> target` + `Remove target` (old inode) + `Create target` (new inode). The watcher MUST handle:

1. The new target inode is not automatically watched — `Add(dir)` (not `Add(file)`) means the watcher sees directory-scoped events, so renames into the dir are caught.
2. Debounce collapses the storm into one reload.
3. If `Add(file)` were used instead, the watcher would stop tracking after the rename. **Slim variant uses `Add(dir)` exclusively** — same approach `fsnotify` README recommends.

## 5. Test plan (B / A / A+ tiers)

Per `feedback_grade_rubric` — tool-checkable, distinct per tier. T-HR is the only new task; T1 + T4 tests stay.

### B — floor (ships)

- `TestReloader_SighupTriggersReload` — sends SIGHUP to the process; assert `CurrentRevision` advances when on-disk `.rego` content changed; stays same when content unchanged (short-circuit).
- `TestReloader_FsnotifyTriggersReload` — writes a new `.rego` into `policy_dir`; assert reload fires within debounce + 50 ms slack.
- `TestReloader_HalfWrittenFile_RetainsLastGood` — write a `.rego` with intentional syntax error; assert `CurrentRevision` unchanged + log carries `regatta.authz.reload.failed`.
- `TestReloader_IgnoresEditorBackupFiles` — write `approval.rego.swp` + `approval.rego~` + `.approval.rego.tmp`; assert ZERO reload events.
- `TestReloader_BootHydrateFromDisk` — start Reloader against pre-populated dir; assert `CurrentRevision` matches disk SHA before any signal/fsnotify event.
