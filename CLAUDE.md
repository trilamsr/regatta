# Regatta — Agent Operating Rules

Single source of truth for any agent (main session, subagent, CI) operating in this repo. Subagents do NOT inherit `~/.claude/projects/.../memory/` — rules below MUST be self-sufficient. Memory dir stays per-operator (personal preferences only); load-bearing rules live here.

When a rule cites `feedback_<slug>`, the slug is an inline anchor for cross-reference; the canonical text lives here in CLAUDE.md. Operator memory files under `~/.claude/projects/<hash>/memory/` are personal and not load-bearing — do NOT `Read` them.

Fleet-scope rules (parallel-implementer polling cadence, reviewer-wave prefetch, dispatch orchestration) live in `docs/engineer/autonomous-loop.md` — read only when running the autonomous loop.

## Decision priority (apply to every choice)

UX > ease > performance > best-practices > speed > velocity. Long-term > short-term. NEVER ask user — spawn review subagent + decide via these rules. Tool-checkable facts: verify, never ask. (`feedback_decision_priority`, `feedback_verify_before_asking`)

**Default simpler**: Pick the simplest viable option. Don't pre-build lint scripts / abstractions / tier systems for hypothetical drift. Anti-pattern: "what if 5 PRs/month land outside the list" — wait for the 5 PRs, not the lint. Three similar lines beat a premature abstraction. (`feedback_default_simpler`)

- **Recognize session end**: "address N items" is a hint, not a contract. When non-phase-x non-soak-gated open issues drop to ≤2, report "actionable surface exhausted" + offer phase-x triage / wedge triage / stop. Don't fabricate items, don't re-touch swept files, don't build lint scripts for hypothetical drift. (`feedback_recognize_session_end`)

## Token economy (subagent-injection rules)

- **Dispatch brief only**: implementer subagents receive per-task brief (spec §12 style), NOT full spec doc. Main thread keeps full spec for cross-cutting Qs. (`feedback_dispatch_brief_only`)
- **No memory re-read**: never `cat`/`Read` files under `~/.claude/projects/<hash>/memory/`. Reference by slug only. Exception: editing the memory file itself. (`feedback_no_memory_reread`)
- **Worker-prompt parity gate**: every `feedback_*` slug listed under `docs/engineer/dispatch-templates/implementer.md` `## Anchored rules (worker-prompt parity)` MUST be cited in `internal/orchestrator/spawner/claude.go::defaultPromptBuilder`. `scripts/check-prompt-parity.sh` enforces; dispatch template is authoritative. Escape hatch: append ` <!-- prompt-parity-skip: <reason> -->` to a bullet kept reviewer-only.
- **Subagent ci-check compress**: implementer reports `make ci-check` via the canonical PIPESTATUS-safe pattern below + exit code. Naive `cmd | tee | grep | tail; echo "exit=$?"` samples TAIL's exit, NOT make's — a green tail next to a red make ships a false "exit=0" claim. Use Pattern A (`set -o pipefail`): `set -o pipefail; make ci-check 2>&1 | tee /tmp/cicheck.log | grep -E "^(FAIL|ok|---|Error|error:|PASS)" | tail -40; echo "exit=$?"`. Or Pattern B (rc capture): `make ci-check 2>&1 | tee /tmp/cicheck.log; rc=$?; grep -E "^(FAIL|ok|---|Error|error:|PASS)" /tmp/cicheck.log | tail -40; echo "exit=$rc"`. Main thread re-runs full (~10% lie rate). (`feedback_subagent_cicheck_compress`, `feedback_subagent_verification`)
- **No `while pgrep / sleep` babysit loops on long-running commands** — run `make check` in the FOREGROUND, OR use the harness Monitor tool for notification-based completion. Chained `until ! pgrep ...; do sleep ...; done` patterns burn 30-50min idle per implementer (efficiency audit 2026-06-21). The babysit-loop adds zero signal beyond `Bash(run_in_background=true)` + harness notification. (`feedback_no_pgrep_sleep_babysit`)
- **Default to Grep + offset+limit Read** — full-file Read only when about to Edit AND the file is ≤300 lines. Otherwise `Grep` first to locate, then `Read` with `offset + limit` (max 200 lines). Audit 2026-06-21 found 45-73% of implementer Reads were unnecessary full-file pulls on 800-1500 LOC files — the model needed lines N-N+50 and ate the rest as silent context. (`feedback_grep_first_read_targeted`)
- **Explicit completion signal** — every implementer / reviewer subagent MUST end its session with ONE final Bash call: `echo "AGENT_DONE: <role> <key=val>..."` (implementer: `pr=<N> branch=<branch> sha=<sha>`; reviewer: `verdict=<APPROVE|REVISE|BLOCK|INSUFFICIENT_EVIDENCE> count=<N>`). Silent-ends leave the harness uncertain whether the agent is still running — operator wastes 30-60min polling transcript-mtime per offender. Canonical operator cross-ref: `feedback_agent_liveness_not_timestamp`. Worker-prompt parity gate enforces presence in `defaultPromptBuilder`. (`feedback_explicit_completion_signal`)

## Identity / output

- **No AI signatures anywhere** — no `Co-Authored-By`, no `🤖 Generated with`, no "written by Claude" in commits, PR bodies/titles, code comments, generated docs. (`feedback_no_signatures`)
- **Root cause only** — fix the primary failure mode, not the symptom. Bug downstream → check upstream API contract. Race → check locking design, not lock primitive. (`feedback_root_cause`)
- **Deletion default** — every PR answers "what got smaller?" (LOC, feature, abstraction, primitive, dep). Pure-addition PRs require A+ defense in body. Adversarial reviewer hunts deletion. (`feedback_deletion_default`)
- **Verify premise before deletion** — BEFORE any deletion / untracking PR, grep for what CONSUMES the target: `git grep <basename> -- . ':!.gitignore'` PLUS check `docker-compose*` / `Dockerfile*` / `*.yaml` volume mounts + CI configs. A file that is gitignored BUT tracked (`git ls-files <path>` non-empty AND path matches a `.gitignore` rule) is deliberately-committed infra, NOT junk — judging it cruft and deleting it breaks runtime. Distinct from the stale-ref sweep below: that strips refs TO a deleted symbol; this verifies the target is safe to delete AT ALL. Closes #1290. (`feedback_premise_before_deletion`)
- **Deletion sweep** — when a PR deletes a file or symbol, the author MUST run `git grep` for the basename + stem across the WHOLE worktree (not just adjacent files) BEFORE opening the PR; strip stale references in the same PR. `scripts/check-stale-refs.sh` (in `make check`) enforces fail-closed. Escape: `<!-- stale-refs-justified: <reason ≥4 chars> -->` in PR body for historical-accuracy references in shipped specs. Reviewer subagent re-runs the grep before APPROVE per `docs/engineer/dispatch-templates/reviewer.md §lens 2`. (`feedback_deletion_sweep_full_repo`)
- **Drop ceremony** — skip 10 zero-reward steps unless feature-grade + load-bearing: mid-stream CHANGELOG bumps, "Root causes addressed" tables on mechanical PRs, decorative PR-body sections, per-commit linting noise, etc. (`feedback_drop_ceremony`)

## Comments discipline

- **WHY not WHAT** — default to no comment. A clear name+signature needs no preface. Drop single-line WHAT-narration. (`feedback_comments_discipline`)
- **Long-term-benefit gate** — keep a comment only if removing it would leave a future reader confused about WHY. Sweep on push.
- **Lint reconcile** — exported godocs MUST open with the symbol name AND capture WHY in 1 sentence: `// UpperBound is the inclusive ceiling enforced by the budget gate.` GOOD. `// UpperBound returns the upper bound.` BAD. (`feedback_comments_lint_reconcile`)
- **Test/Fuzz/Benchmark godocs: 1 line max** — `scripts/doc-check.sh` test-godoc gate rejects multi-line. Collapse to `// TestX asserts O on I (#N).` (`feedback_test_godoc_one_line`)
- **Comment budget enforcement** — dispatch prompts say "WHY not WHAT" but implementers drift; reviewer comment-sweep is the backstop. Implementer hard rules + reviewer MED-severity sweep live in `docs/engineer/dispatch-templates/implementer.md` §Comments + `reviewer.md` lens 9. (`feedback_comment_budget_enforcement`)

## CI gates (local pre-push)

- **`make pre-push-check`** before every push (= `make check` + PR-body release-notes-block sanity).
- **Fast precheck before `make check`** — implementer runs `go build ./... && go vet ./<changed-pkg>/...` FIRST (~5s) on every iteration; only escalate to `make check` (~60s) once build+vet are green. Fail-fast on syntax/typos/import-cycles at ~1/12th the cost of full `make check`. Precheck reduces the iteration loop cost, not the gate count. (`feedback_compile_precheck`)
- **Pre-push `make check` MANDATORY** — every dispatched implementer subagent MUST run the full `make check` exactly ONCE before `git push` and verify exit=0. Per-commit `make check` runs are NOT required; during iteration, prefer `go test ./<changed-pkg>/... -short` (~5s) for the package(s) the commit touches. Use the canonical PIPESTATUS-safe form per `feedback_subagent_cicheck_compress`. Never push broken state; fix root cause + re-run. (`feedback_pre_commit_make_check`)
- **`make check`** — authoritative target list lives at `Makefile.d/ci.mk::check`; run `make help` for descriptions. `check-no-bare-sleep` fails closed on `time.Sleep` lexically nested inside a `for` block in any `*_test.go` — migrate to `testutil.Eventually` / `testutil.EventuallyT` / `testutil.AssertStable`, or annotate `// allow-sleep: <reason>` for legitimately non-polling waits.
- **`make ci-check`** = `check stale-todo`.
- **Banned-phrase gate** (`scripts/doc-check.sh`): rejects `blazing[- ]fast`, `production[- ]grade`, `world[- ]class`, `seamless`, `cutting[- ]edge`, `state[- ]of[- ]the[- ]art`, and 5 more (11 total). Wrap literal token mentions in backticks. Reword hits to falsifiable claims. Tag spec-only PRs with `[DOCS]`/`[CI]`/`[CHORE]` release-notes prefix to skip check-tdd. (`feedback_ci_gates`)
- **check-tdd cross-package satisfaction** (`scripts/check-tdd.sh`): a prod `.go` file is satisfied by a co-located `*_test.go` walking up shared ancestors, OR by a whole-word match of a newly-added exported identifier in any `*_test.go` in the PR diff. (`feedback_ci_gates`)
- **PR body hygiene**: `gh pr create`/`gh pr edit` MUST use `--body-file <path>` (HEREDOC escapes backticks + silently breaks release-notes fence). Pre-push grep for triple-fence ` ```release-notes ` block presence. (`feedback_pr_body_hygiene`)
- **Bounded CI poll**: every `gh pr` watch loop MUST have an explicit failure-exit branch + iteration cap (default 10). Forbidden: `until [SUCCESS]; do sleep N; done` — silently hangs on BLOCKED/FAILED CI. Pattern: check `gh pr checks <N>` for `fail` conclusion EACH tick; break on first failure with summary line. (`feedback_bounded_ci_poll`)
- **Windows path tests**: when test assertions compare path strings, canonicalize BOTH sides the same way production code does — or platform-branch the test inputs. 8.3 short-names + `/etc`-literal paths break Windows CI. (`feedback_windows_path_tests`)
- **Byte-equal-refactor pin**: any refactor whose correctness story is "target/gate/route set is byte-equal pre/post" MUST ship a mechanical drift gate (template: `scripts/check-prompt-parity.sh`). PR-body claim alone is rejected — drift surfaces in the next sibling PR, not in this one. `scripts/check-byte-equal-pin.sh` runs as a `make pre-push-check` hint (informational, never fails the push); reviewer-subagent dispatch (per `feedback_adversarial_review`) covers the drift class. Closes #985 #1031.

## TDD + review

- **Failing test FIRST**, capture failing output in PR body, then impl, then green. Order matters; commit log must show the failing test landed first. (`feedback_tdd_discipline`)
- **Honest TDD claims** — red-first ORDERING is load-bearing: the failing test MUST land in a SEPARATE commit BEFORE the impl commit so `git log --reverse <branch>` shows red→green. NEVER claim "red-first" / "TDD" in a PR body when test + impl ship in ONE commit. If a single commit is genuinely unavoidable, state that truthfully + justify. (`feedback_honest_tdd_claims`)
- **Co-located test required**: every prod `.go` file added or modified in a PR MUST carry a co-located `*_test.go` in the SAME package with a test exercising the changed symbol. Cross-package satisfaction via `scripts/check-tdd.sh` works but is brittle (#1057) — same-package is always preferred. Anchored in `docs/engineer/dispatch-templates/implementer.md` and cited inline by `internal/orchestrator/spawner/claude.go::defaultPromptBuilder` (parity gate enforces). (`feedback_colocated_test_required`)
- **Independent reviewer subagent** on every load-bearing PR (security, concurrency, schema, public API). Adversarial framing: hunt edge cases, don't auto-approve. Every load-bearing artifact gets an adversarial pass — not just PRs. Design briefs, specs, prompt templates, operator-facing decisions. Builder spawns inline reviewer OR explicitly skips with cited `feedback_review_proportional` predicate. (`feedback_adversarial_review`, `feedback_adversarial_review_every_step`)
- **Reviewer-verdict gate** (`scripts/check-reviewer-verdict.sh`, wired into pr-lint workflow): load-bearing PRs (paths under `internal/{ghclient,gates,orchestrator,supervisor,ghidempotency,secrets,sandbox,web,obs,cost,canon}/`, `cmd/`, `contracts/`, PLUS CI-gate surfaces `Makefile`, `Makefile.d/*`, `.github/workflows/*`, `scripts/check-*.sh`) MUST carry BOTH `Reviewer-agent-id: <id>` AND `Reviewer-recommendation: APPROVE` in the PR body footer (bare, not in a code block). Missing recommendation / APPROVE without agent-id / `REVISE`/`BLOCK` → fail. `[CHORE]`/`[DOCS]`/`[CI]`/`[NONE]`/`[CHANGE]` release-notes auto-skips — EXCEPT when path classifier flags an agent-rule / CI-gate / load-bearing-doc / operator-UX / event-vocabulary surface. Agent-id token is honor-system — dispatch discipline (only paste a real subagent ID returned by the agent runtime) keeps it truthful.
- **Doc-link gate** (`scripts/check-doc-links.sh`, in `make check`): markdown-link form `](path)` under `docs/` + `CLAUDE.md` whose path starts with `docs/`/`internal/`/`cmd/`/`contracts/`/`scripts/`/`Makefile.d/` MUST resolve at HEAD.
- **Cite origin/main, not local worktree** — every repo-internal citation in a brief / spec / dispatch-template MUST resolve against `git ls-tree origin/main`, never the author's worktree state. Numeric claims MUST be paired with the exact command that produced them. License + version claims for OSS prior art MUST cite LICENSE-file URL / SPDX content + resolvable tag-ref. Reviewer subagents re-run the commands. (`feedback_cite_origin_main_not_local`)
- **PR not done until merged**: `mergedAt != null` AND `state = MERGED`. Automerge enabling + 'CLEAN' status + 'approved' DO NOT count. Post-approval CI flake regularly leaves PR in OPEN/BLOCKED limbo. Watch via `gh pr view N --json state,mergedAt,mergeStateStatus,statusCheckRollup` until terminal. (`feedback_watch_pr_until_merged`)
- **Reviewer findings → tracking issues**: every CRITICAL/HIGH/MED adversarial-review finding NOT addressed inline → file tracking issue BEFORE marking PR merge-ready. PR bodies are not durable; reviewer comments evaporate. Issue title: `[REVIEWER #PR] <severity> <category>: <claim-summary>`. (`feedback_reviewer_findings_to_issues`)
- **Skip reviewer when proportional**: dep bumps with CI green + <20 LoC + no API change, PR-body-edit-only, trivial doc strips. Auto-skip when `git diff --name-only origin/main...HEAD | grep -vE '^(docs/|\.github/|scripts/|.*\.md$)'` returns empty. **Small-PR [FIX] auto-skip**: `[FIX]` PRs with `git diff --shortstat` insertions+deletions <50 AND no load-bearing path matched auto-skip. `[CHORE]/[DOCS]/[CI]/[NONE]/[CHANGE]` already auto-skipped without a LoC threshold. Workflow passes `--loc-delta` from `git diff --shortstat`. (`feedback_review_proportional`)
- **Spec pattern authority**: implementer deviation → re-spawn design subagent. NEVER let implementer pick pattern. (`feedback_spec_pattern_authority`)
- **Risk-tier findings**: fix inline OR file tracking issue + cite #. Never auto-approve with unaddressed Risk+. (`feedback_review_before_automerge`)
- **Unaddressed load-bearing**: every load-bearing leftover (reviewer finding, spec deviation, future-wave dep sketched in prose) → tracking issue filed BEFORE merge. PR bodies are not durable. Universal rule, no PR-type exempt. (`feedback_unaddressed_load_bearing`)
- **Audit before dispatch / before building**: before dispatching an implementer for a plan-master task — AND, for the worker, before writing any code — verify the work isn't already on main: `git ls-tree -r origin/main --name-only | grep <expected-path>` OR `git log --oneline origin/main | grep '(#<task-issue>)'`. The worker self-aborts + reports "already shipped" if the target exists. (`feedback_audit_main_before_implementing`)
- **Validate empirically + verify subagent output**: Before recommending CI/perf/memory changes OR dispatching action on subagent findings, run a local measurement (`/usr/bin/time -l go test -race ...` resolves debates in 1min) AND spot-check 2-3 file:line refs from investigator/reviewer reports. Subagent output is a LEAD, not GROUND TRUTH. (`feedback_validate_before_ship`, `feedback_subagent_output_verify`)
- **No self-tagged `Reviewer-recommendation: APPROVE`**: author writing own APPROVE token == zero adversarial pass. Spawn `cavecrew-reviewer` (or equivalent independent agent) in fresh slot BEFORE the token lands; if reviewer finds HIGH/MED, fix inline OR file tracking issue + cite # before writing APPROVE. **Mechanical enforcement**: `scripts/check-reviewer-verdict.sh` requires `Reviewer-agent-id:` on load-bearing PRs to match an independent-reviewer allowlist: harness shape `^a[0-9a-f]{16}$` OR named subagent `^(cavecrew|designer|triage|implementer|reviewer)-<slug>$`. Anything else fails closed. When `--pr-author <login>` is passed, the gate additionally fails when `Reviewer-agent-id:` equals the author login. Operator escape (rare, trivial doc/typo/dep-bump only): `<!-- reviewer-skip-justified: <reason ≥4 chars> -->` in PR body. Operator-opened PR escape: `<!-- operator-opened: <reason ≥4 chars> -->` in PR body — bypasses author-mismatch only; allowlist + token-present checks still run. **Fabricated agent-id = void verdict**: main thread MUST verify the value against the session's dispatched-reviewer registry BEFORE writing the token. **Reviewer must pin to pushed commit, not worktree** — adversarial subagents read via `gh pr diff <N>` / `git show <sha>:<path>`, NEVER the live worktree bytes; dirty worktree review = void verdict. (`feedback_no_self_tagged_approve`)
- **No implementer-enabled automerge**: implementer subagents MUST NOT run `gh pr merge --auto` (or any automerge-enabling form). End with `gh pr ready <N>` + operator-merge handoff. **Mechanical enforcement**: `scripts/check-reviewer-verdict.sh` queries `gh pr view --json autoMergeRequest`; when `autoMergeRequest != null` AND the PR is load-bearing AND `Reviewer-agent-id:` is present, the gate fails closed with stderr token `automerge_with_agent_id_on_load_bearing`. Operator can always disable automerge (`gh pr merge --disable-auto <N>`) then merge manually. (`feedback_no_implementer_automerge`)
- **Stop at `gh pr ready` (no implementer self-revise)**: after pushing + opening PR + running `gh pr ready <N>`, the implementer subagent MUST STOP. No self-revise commits, no pre-emptive fixups against potential reviewer findings, no further pushes. Wait for explicit feedback from operator-dispatched independent reviewer OR operator. Self-revising races operator reviewer dispatch: operator dispatches reviewer against commit SHA X; implementer pushes SHA Y mid-flight; reviewer report cites code that no longer exists. Rule lives in `docs/engineer/dispatch-templates/implementer.md` §STOP AT `gh pr ready` and is parity-anchored. (`feedback_stop_at_pr_ready`)
- **Validate after shipping**: PR not done at green CI; done when merged behavior matches the claim under real workload. LIVE validation preferred. When live validation impossible, the test suite MUST cover the behavior end-to-end; TDD mandatory — failing test for post-ship behavior lands FIRST. Check obvious neighbor modules; file follow-up issue the moment a regression appears.
- **Verify-CANCELLED + orphan test = goroutine leak**: when GitHub Actions verify job is CANCELLED at full job timeout and the log shows `ok` for all packages followed by silent minutes then `##[error]The operation was canceled.` and `Terminate orphan process: pid (N) (sometest.test)`, root cause is a goroutine inside one test blocking on a channel that is closed only in a `defer` that never fires because the test func never returns. Fix with `select { case <-ch: case <-time.After(deadline): }`. (`feedback_ci_timeout_orphan_test_goroutine`)
- **Double-fail = root cause**: same test/gate failing twice in one session is a real defect, NOT a flake. Stop retrying on the second hit; investigate root cause. Retrying around the symptom costs CI cycles + masks the structural defect. (`feedback_double_fail_root_cause`)

## Worktree discipline

- **Agents always in worktrees** (`.claude/worktrees/agent-<id>/`). Main checkout is read-only (`git fetch`, `git log`, `git status`). Never push from primary.
- **Keep orchestrator-pinned branch name**: spawned worker MUST push under the orchestrator-assigned `regatta/agent-<N>` ref. `git checkout -b <semantic>` inside the worktree hides the PR from `prwatch.Sweep` (`gh --head regatta/agent-<N>` returns 0; agent stays `running` forever; reaper never fires; worktree leaks). Semantic name belongs in the PR title. Mechanically enforced via `scripts/check-prompt-parity.sh`. (`feedback_keep_orchestrator_branch_name`)
- **Never `git clone` or `git worktree add` from a subagent** — the harness pre-creates the worktree at `.claude/worktrees/agent-<id>/`; subagent only `cd`s to it. Writing under `/tmp/regatta-<slug>/` leaves stray edits in main worktree with no pushable branch. (#188)
- **One writer per worktree**: never dispatch a second agent into a worktree until the prior owner is confirmed terminal — completion notification received, OR `TaskStop` returns not-running, OR pushed-commit sha matches what the agent reports. Stale agent-output file mtime is NOT a death signal: the prior owner may be deep in `make check` or sub-review and silent. Re-dispatching clobbers HEAD, loses uncommitted work, produces silently-mixed-author commits that void any subsequent reviewer pass. Canonical operator slug: `feedback_agent_liveness_not_timestamp`.
- **Per-merge cleanup**: `git worktree remove --force` after merge. Force-twice clears locks: `git worktree remove --force --force <path>`.
- **Post-removal hygiene**: `golangci-lint cache clean` after worktree removal (cache holds stale per-file analysis refs). (`feedback_worktree_discipline`, `feedback_post_worktree_removal_hygiene`)
- **Rebase conflict resolution**: During `git rebase origin/main`, `--theirs` = PR commit being replayed (counterintuitive vs merge); `--ours` = main. Wrong choice silently drops PR work (lost #772). Sibling-stack PRs (branched off another in-flight feature, no merge-base with main) MUST use `git rebase --onto origin/main <sibling-base> <pr-branch>` — plain `rebase origin/main` replays the sibling's commits as massive add/add conflicts. Verify merge-base first. Snippet: `git checkout --theirs <file>` → `git add <file>` → `git rebase --continue`. (`feedback_rebase_theirs_vs_ours`, `feedback_rebase_onto_for_sibling_stacks`)
- **Primary checkout always on `main`**: primary checkout MUST always be on `main`. Feature branches in primary block subagent worktrees from grabbing the same branch — git refuses checkout. If primary drifts, immediately `git checkout main && git pull --ff-only origin main`. (`feedback_primary_checkout_always_on_main`)
