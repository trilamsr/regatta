## Summary

`cmd/gh-followup-to-items` — converts GitHub `[followup]`-labeled issues into `.regatta/items/gh-issue-<n>-<slug>.md` briefs so the existing markdown_catalog adapter ingests them as `WorkItem`s. Sibling of S1-T3 (`cmd/boot-prompt-to-items`, #331). Closes part of #342.

Spec: `docs/engineer/specs/2026-06-02-s2-t3-followup-triage.md` (branch `spec/s2-t3-followup-triage`, PR #342 CLEAN).

`make followups` runs `go run ./cmd/gh-followup-to-items`. Shells to `gh issue list --label followup --state all --json ...`. Auth via `GH_TOKEN` env (inherited by `gh`; never read by this binary).

## What got smaller

- No new schema. No new adapter. No new orchestrator wiring. No new third-party Go dep. No new GH label.
- No `--include-closed`, no `--force`, no verbosity flag. (YAGNI.)
- No `--state` flag (operator-facing) — `--state all` is internal to keep the §6 cleanup pass honest (spec §7 AR-1).
- Closed issues do not emit a `status: completed` (no such state in schema) — file is deleted instead (spec §6 option C).
- No `dependencies:` frontmatter — `gh issue view --json` does not surface sub_issues today (spec §3.3); tracking issue filed at spec-time.
- No shared `internal/itemsgen/` package — premature abstraction; defer to the 3rd sibling caller (spec §2.1).

## Implementation notes vs spec

Two spec contradictions surfaced during TDD; flagged here for the next design pass:

1. **Spec §3.2 lane derivation.** Prose says "pick first `*-followup$`" but the same section's table maps `followup`+`tech-debt` → `tech-debt` (no `-followup` suffix). Implementation picks the alphabetically-first non-`followup` label, lower-cased; this satisfies BOTH the table AND the determinism rule. Tracked inline in `deriveLane` godoc.
2. **Spec §3.4.1 mitigation #1.** Spec proposed wrapping body in a `` ```text ... ``` `` fenced block when the body itself contains `## Acceptance criteria`. The adapter's `parseCriteria` walks raw lines and is fence-blind, so fencing alone does not defang the regex (`criteriaHeadRE = ^##\s+acceptance\s+criteria\s*$`). Implementation prefixes such lines with `> ` (markdown blockquote); the leading `> ` breaks the anchor, preserves human-readability, and is verified by `TestParse_BodyContainsAcceptanceHeading` against the real `adapter.ParseMarkdownItem`. Documented in `renderItem` godoc.

Both deviations follow `memory/feedback_root_cause` (fix the real defect) and `memory/feedback_research_design_principles` (adapter is the source of schema truth; the converter MUST round-trip through it). Per `memory/feedback_spec_pattern_authority`, these are surfaced for the next spec revision.
