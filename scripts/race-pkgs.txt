# Go packages whose code (PROD or TEST) uses concurrency primitives
# (sync.{Mutex,RWMutex,Once,WaitGroup,Map,Pool,Cond,Locker}, channels,
# `go func`, named-goroutine launches, atomic.{Add,Store,Load,Swap,
# CompareAnd,Bool,Int,Uint,Pointer}). These packages run `go test -short
# -race`; everything else runs without `-race` to halve test-binary build
# + run time.
#
# Why include _test.go in the scan: even when a package's PROD code is
# single-threaded by design (e.g. internal/orchestrator/prwatch runs on
# the orchestrator tick driver, no goroutine of its own), tests routinely
# fan out goroutines against test fakes — those races must be caught too.
#
# Nightly cross-platform-nightly.yml ALSO runs `go test -short -race ./...`
# across the full tree on ubuntu / macos as a backstop, catching any race
# in a package whose code hides concurrency from the scan regex.
#
# Regenerate via scripts/regen-go-shards.sh (see docs/engineer/pointers.md).
